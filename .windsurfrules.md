# Project Rules for Browser-to-ComfyUI Extension

## Build & Tooling
- Use Vite as the build tool for bundling TypeScript to JavaScript for the Chrome extension.
- Run `npm run build` for production builds that compile and bundle all scripts to the `dist/` directory.
- Run `npm run dev` for development builds with watch mode for automatic rebuilding during development.
- The build process outputs separate JS files for background, popup, and options scripts as specified in `vite.config.ts`.

## Testing Frameworks
- Use Jest or Vitest for testing browser extension logic.
- Focus tests on:
  - Storage helpers (getSettings, saveSettings, getHistory, saveHistory)
  - ComfyUI API client (sendToComfyUI, buildComfyUIWorkflow)
  - Popup UI logic (rendering history, handling user interactions)
  - Background script behaviors (context menu, keyboard shortcuts)
- Mock Chrome APIs using jest-chrome or similar for testing extension-specific functionality.

## Coding Standards
- Use TypeScript for all extension scripts (background.ts, popup.ts, options.ts).
- Follow strict typing with explicit types for all functions, props, and variables; avoid `any`.
- Use camelCase for variables, functions, and methods; PascalCase for components and types.
- Organize code into separate modules: types.ts for interfaces, utils.ts for shared functions.
- Add comprehensive inline comments around all ComfyUI-related integration points, such as workflow JSON construction and response parsing.
- Comment on browser-API-specific behaviors like context menus, commands, and storage operations.
- Use ESLint and Prettier for code linting and formatting to maintain consistent style.

## Project Conventions
- Structure the project with `src/` for TypeScript sources, `dist/` for built files, and root level for manifest and HTML files.
- When adding new features:
  - Create new modules in `src/` for specific functionalities (e.g., apiClient.ts for ComfyUI interactions).
  - Update the background script to wire in new event listeners or permissions.
  - Add UI components to popup.ts or options.ts as needed.
- To add new configuration options:
  - Define the option in ComfyUISettings interface in types.ts.
  - Add form fields to options.html and logic to options.ts.
  - Persist via chrome.storage.sync and access via getSettings in other scripts.
- Encourage small, focused commits with descriptive messages (e.g., "Add auto-send toggle to popup UI").
- For multi-workflow support or additional sliders (CFG scale, steps), extend the ComfyUIPayload interface and buildComfyUIWorkflow function without rewriting core storage or UI logic.
